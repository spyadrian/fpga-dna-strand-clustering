## Monday : 16 June

I received the access to the Self-Service Licensing Center, but it's better if my teacher get the license on his account as my account will be deleted when I leave the school.
Waiting for the license, I kept analysing the code.

The most important part of the code in inside the `OneJoin` function.
Inside it are all the steps of the algorithm :

| # | **Step name**                 | C++ function | What it does                                                                                | ≈ % of total time\* |
| - | ----------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------- |
| 1 | Initialization                | `initialization(...)` and helper timers       | Parses CLI-params, builds LSH tables, allocates host/device buffers and seeds RNGs                       | **≈ 3 %**           |
| 2 | Embedding                     | `parallel_embedding_wrapper`                  | CGK-embeds every read (many replicas) in parallel on all available SYCL queues | **≈ 12 %**          |
| 3 | Bucket creation               | `create_buckets_wrapper`                      | Hashes each embedded vector, materialises and sorts (randStr, hashFn, hashID) tuples to form LSH buckets | **≈ 20 %**          |
| 4 | Init for candidate generation | `initialize_candidate_pairs`                  | Scans the bucket array once to pre-size the candidate vector and record bucket boundaries                | **≈ 5 %**           |
| 5 | Candidate generation          | `generate_candidates_wrapper`                 | Enumerates every unique pair inside each bucket in a GPU/CPU kernel and writes compact candidate tuples  | **≈ 20 %**          |
| 6 | Candidate processing          | cand-proc block inside `onejoin()`            | Filters impossible pairs, parallel-sorts & de-duplicates the list, preparing it for verification         | **≈ 15 %**          |
| 7 | Counting frequencies          | `cand_proc::count_freq` section               | Counts how many times each unique pair appears so low-support pairs can be pruned                        | **≈ 10 %**          |
| 8 | Edit distance verification    | `verify_pairs` → `edit_distance`              | Multi-threaded Levenshtein verification emits the finally similar read pairs                             | **≈ 15 %**          |

_The time was generated by chatGPT and is therefore indicative ("Percentages sum to ~100 % and come from the profiling numbers in the GEN-470 KS experiment")._

Before trying the FPGA simulator I push some useful file on the git :

- `dataset/` : all the dataset I generated
- `external/oneoligo` : the oneoligo Git as a sub-module
- `patches/oneoligo-local.patch` : a patche for the oneoligo Git
- `scripts/apply-patches.sh` : a script that apply the patch on the oneoligo Git

The sub-module and the patch was created with : 

```
git submodule add https://github.com/Eug9/oneoligo.git external/oneoligo
git commit -m "add module oneoligo as a submodule"
git config submodule.external/oneoligo.ignore all

// add flag in Makefile and fix ambigus floor

git diff > patches/oneoligo-local.patch
```

The script `apply-patches.sh` create the directory build before applying the patch.
So don't forget the `--recurse-submodules` when cloning the repo.
